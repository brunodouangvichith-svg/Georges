# Web app

Moved verbatim from `CLAUDE.md`.

## `web/` — the front-end app

### Commands
Run from `web/`:
```
npm install       # install deps
npm run dev       # Vite dev server on :5173 — no longer allowed by default: needs CORS_EXTRA_ORIGINS=http://localhost:5173 on the API it calls (production web is the Render site george-web)
npm run build     # production build (outputs to dist/)
npm run preview   # serve the production build locally
npm run lint      # oxlint (see .oxlintrc.json)
npm run test      # vitest run — component tests, hooks mocked, no API/Docker needed
```
Copy `.env.example` to `.env` to override `VITE_API_BASE_URL` (default `http://localhost:8000`, read in `src/api/client.js`).

### Stack
Vite + React 19 + Tailwind CSS v4 (via `@tailwindcss/postcss`) + Recharts (donut chart in Paniers) + [`@tanstack/react-query`](https://tanstack.com/query) (all API calls/caching — task 9 of the Phase 3 prompt) + Vitest/React Testing Library/jsdom (dev-only, task 10). No router — view switching is plain `useState` in `App.jsx`. No `lucide-react` any more (dropped with the Paniers rewrite below — check before re-adding an icon library that nothing else needs it).

### Architecture
- **`src/api/client.js`** is a thin `fetch` wrapper (`apiFetch(path, params)`) — throws on any non-OK response so React Query's `isError` fires correctly. **`src/api/queries.js`** has one React Query hook per API endpoint (`useSecurities`, `useSecurityPatterns`, `useSecurityPrices`, `useBaskets`, `useGeorgeIndex`, `useDecisions`, `useAgentActivity`). There's no batch endpoint for "pattern + price history for N securities at once", so `WatchlistRow` and `GeorgeIndexTile` each call their own per-item hook — real N+1 request behavior, acceptable at CAC-40 scale, called out in `queries.js`'s docstring as something to revisit if the tracked universe grows a lot.
- **`src/components/CandlestickChart.jsx`** no longer generates synthetic candles from a seeded PRNG (that whole approach — and `src/lib/ohlc.js` — is gone). It now takes real `candles` (from `/securities/{symbol}/prices`) plus the real `context` dict from `patterns_detected`/`PatternOut.context`, and derives the overlay generically from that context's shape rather than regex-matching the pattern name: a `{index, price}` value becomes a marker (translated by the `indexOffset` prop — see the API section above for why that offset is needed), a `{points, price}` value (a neckline) becomes markers *and* a horizontal line, and a bare number under the key `resistance`/`support` becomes a line with no marker. No context at all (no active pattern) means no overlay at all — it no longer fabricates one from local extrema, unlike the Phase-3-prototype version. `takeProfit`/`stopLoss` are now absolute prices (from `Decision`), not the old `tpPct`/`slPct` percentages off a synthetic last close.
- **`src/views/Univers.jsx`** fetches `useSecurities`, `useDecisions` (built into a `symbol -> most-recent-decision` map client-side — there's no per-symbol decision filter on the endpoint, and the full list is small enough to fetch once), `useBaskets`, `useAgentActivity` at the top level; `WatchlistRow`/`GeorgeIndexTile` (in `src/components/`) own their own per-item queries. The George Index tile grid always renders exactly 2 slots (real tile, or an empty filler `<div>`) plus the macro tile — the grid's `gridTemplateColumns` is the fixed `"150px 150px 1fr"`, so a *variable* number of basket tiles (0, 1, vs. 2) shifts the macro tile into the wrong column; the empty-baskets message instead spans both slots via `col-span-2`. Distinguishes "API unreachable" (`isError`) from "DB reachable but empty" (`data.items.length === 0`) with two different messages — collapsing them into one generic empty state would hide a real connectivity problem.
- **`src/views/Paniers.jsx`** was rewritten from a fictive-portfolio simulator (invented capital, position weights, cash reserve — none of that has a backing table in the schema) into a real-data basket/decision browser: George Index per basket (bars, real), universe breakdown by `sector` (donut, real, computed client-side from the single `/securities` fetch rather than a per-basket count query), and a real `/decisions` table. Same "unreachable vs. empty" distinction as `Univers.jsx` (`apiUnreachable = basketsError || securitiesError || decisionsError`).
- **`src/data.js`** now only holds the `decisionColor`/`scoreColor` helpers shared by both views — the last fictive placeholder (`macro`, a rates/indices/FX tile with no backing table) was removed once the Energy Market feature (see its own section below) gave the equivalent "Repères macro" tile a real backing table (`GET /energy-prices`). Everything else that used to live here (`positions`, `georgeIndex`, `agentEvents`, `CAPITAL`) is gone now that real data is wired up.
- **Theming** is CSS custom properties defined once in `src/index.css` (`--bg`, `--panel`, `--positive`, `--negative`, etc.), consumed via inline `style={{ color: "var(--x)" }}` or Tailwind arbitrary values rather than a Tailwind theme extension. Keep new components consistent with this pattern instead of introducing hex literals or extending `tailwind.config`.
- **Tests** (`*.test.jsx` next to the files they cover) mock `../api/queries` wholesale with `vi.mock` rather than standing up a `QueryClientProvider` + mocking `fetch` — simpler, and sufficient since the hooks themselves are trivial wrappers with no logic of their own to test. `vi.mock` is keyed by resolved module path, so mocking `"../api/queries"` from e.g. `Univers.test.jsx` also mocks it for `WatchlistRow`/`GeorgeIndexTile` that `Univers` renders, even though those files import it via the same relative specifier resolving to the same file — no separate per-component mock wiring needed.

### PWA + Render static site (Oct. 2026, user request "étape 1")
- `web/` is installable as a PWA via **vite-plugin-pwa 2.0** (`vite.config.js`): manifest (`George`, `#0F1626`, standalone, `lang: fr`), icons in `public/` (`pwa-192x192.png`, `pwa-512x512.png`, `maskable-512x512.png`, `apple-touch-icon.png`, generated with Pillow — navy square, white "G", blue dot), `registerType: 'autoUpdate'`. The service worker precaches only the app shell; **API responses are never cached** (prices/decisions served stale offline would be misleading). `index.html` has the theme-color/Apple meta tags.
- Hosting: `render.yaml` service `george-web` (`runtime: static`, `rootDir: web`, `npm ci && npm run build`, `dist`, SPA rewrite to `/index.html`, `Cache-Control: no-cache` on `/sw.js`). `VITE_*` vars are read **at build time** — redeploy after changing them.
- `LoginScreen.jsx` passes `redirectTo: window.location.origin` to Google OAuth, so each origin (localhost, Render site) must be listed in Supabase → Auth → URL Configuration → Redirect URLs.
- `api/main.py:cors_origins()` = only the origins in `CORS_EXTRA_ORIGINS` (comma-separated, trailing `/` stripped), read at API startup. Production: `george-api` has `CORS_EXTRA_ORIGINS=https://george-web-43l7.onrender.com` (site live since 2026-10-17). **localhost:5173 was removed at the user's request** (no default origin any more, and removed from Supabase Redirect URLs); for local web dev, export `CORS_EXTRA_ORIGINS=http://localhost:5173` before `uvicorn` and re-add it in Supabase. `tests/conftest.py` sets that value by default for the test session (test_api sends `Origin: http://localhost:5173`); `tests/test_cors.py` reloads `api.main` to test other values.

### Market status pill (`web/src/lib/marketStatus.js`)
- The header's "Marché ouvert · 08:30" used to be hard-coded (always "open"). It is now computed client-side in Europe/Paris time and refreshed every 30 s by `Layout.jsx`: open Mon-Fri 09:00-17:30, closed on weekends and Euronext holidays (1 Jan, Good Friday, Easter Monday, 1 May, 25-26 Dec; Easter via the Gregorian computus), 14:05 close on 24 and 31 Dec. Red dot + reason ("week-end", "jour férié", "ouverture à 09:00", "séance terminée") when closed. Tests: `marketStatus.test.js`.

The shared building blocks are the `gd-*` classes in `src/index.css` (`gd-panel`, `gd-label`, `gd-btn`, `gd-tag-*`, `gd-wide`); `data.js:decisionTagClass` maps a decision to its coloured tag (same colours as `decisionColor`).

- **Sector labels are radial (Oct. 2026, user request)**: they used to be horizontal and overlapped near the top/bottom of the circle (e.g. "SANTÉ / BIOTECH" over "SERVICES"). `buildRadar` now returns a `rotate` angle per label (text from the ring towards the centre, left half flipped 180° so it never reads upside down, normalised to [-90°, 90°]); neighbouring labelled sectors are ≥ ~10° apart and a label needs ~3°, so they cannot overlap. - **Radar groups by sector family (Oct. 2026, user asked "où sont les autres secteurs ?")**: `securities.sector` has ~70 sub-sectors ("Santé / Biotechnologie", "Santé / Pharmacie"…), almost all with 1-3 securities, so only 2 got a label. `buildRadar` (web) / `buildRadarLayout` (mobile) now group by family (`sectorFamily`: the part before " / "), put families of < 3 securities in "Autres secteurs" (last), and label every group of ≥ 3 — 12 labels on the real universe. The watchlist and detail panels still show the full sector.

### Univers — liquidité et risque par valeur (nov. 2026, demande de l'utilisateur)
- Dans la fiche « Valeur sélectionnée » seulement (`components/RiskMetrics.jsx`), choix de l'utilisateur : ni info-bulle sur le tore, ni mesures sur les cartes du fil. Volume quotidien moyen (20 séances, en titres), volatilité réalisée annualisée (1 an), ATR 14 (€ et % du cours), bêta et corrélation avec le CAC 40, corrélation avec le secteur (1 an).
- `GET /securities/risk-metrics` renvoie tout l'univers en un appel (`useRiskMetrics`), avec une seule lecture de `price_history_long` (`engine.run_detection.load_recent_prices`, 550 jours). Résultat gardé 5 minutes en mémoire (quelques secondes de calcul), vidé par « Mise à jour des prix ».
- Calculs dans `engine/risk_metrics.py` (conventions en tête de module) : rendements logarithmiques, séance du jour écartée (volume partiel), « — » si l'historique est insuffisant, jamais 0. ATR repris de `engine/features.py` (moyenne simple, pas le lissage de Wilder).
- Le CAC 40 n'est pas en base : `ingestion/index_prices.py` le télécharge chez Yahoo à la demande, cache de 6 h, nouvel essai après 5 min en cas d'échec (choix de l'utilisateur, contre une table avec migration). Indisponible, le bêta et la corrélation avec l'indice sont à « — ». C'est la seule exception à « `price_history_long`, source unique des prix ».
- « Secteur » = famille avant « / », comme sur le tore, car les intitulés complets n'ont souvent qu'une valeur : moyenne équipondérée des **autres** valeurs de la famille, au moins 2 et 227 séances sur 252, sinon « — ».
- Limites : cours ajustés des divisions par Yahoo mais pas des dividendes ; une variation de plus de 50 % en une séance sur la fenêtre est signalée sous les chiffres, sans les masquer (elle peut être réelle, ou une opération sur titres mal ajustée comme sur ATO.PA). Une barre téléchargée en cours de séance reste partielle en base jusqu'à l'import suivant : elle n'est écartée que le jour même.

### "Obligataire" tab — web UI for Obligataire Watch (ad hoc, requested directly by the user)
- `src/views/Obligataire.jsx`: the first web screen for the pre-existing `/bonds` API (`api/routers/bonds.py`) — yield cards with 24h/7j/30j variations, OAT-Bund spread and US 10a-2a slope, a history chart (`components/BondHistoryChart.jsx`, geometry in `bondChartLayout.js`), the deterministic daily bulletin, active alerts, editable thresholds, alert history and collection runs. Manual "Mettre à jour les taux" calls `POST /bonds/refresh` (synchronous, no polling needed).
- **George's original dark theme** (user's explicit request: "bleu/blanc/vert/rouge"), like every other screen. Colour convention shown on screen: a **rate rise is red, a fall green** (financing gets dearer / bond prices fall). Chart series use blue/white/orange/grey (theme variables), never green/red, which are reserved for direction.
- **History backfill**: `ingestion/bond_yields.py:run()` (daily job / "Mettre à jour les taux") only stores the *latest* FRED observation, so a fresh database shows one point per series and "n/d" variations. `python -m ingestion.bond_yields --backfill [years]` (default 10) loads the full FRED history once via the same idempotent upsert (batches of `UPSERT_BATCH_SIZE`), without writing a `bond_collection_runs` row. Production found at migration `0016` on 2026-10-16 (Obligataire page showed "Impossible de contacter l'API": tables from `0018` missing) — fixed by `alembic upgrade head` + seed + backfill run by hand.
- OAT/Bund are monthly series (OECD via FRED), Treasuries daily — `/bonds/{instrument}/history?limit=` counts observations, not days, so the screen always fetches `limit=2000` and filters by date client-side for the 1/3/5-year range buttons.
- **Daily OAT and Bund (Oct. 2026, user request after seeing a 6-week-old OAT)**: `ingestion/bond_yields.py` now tries a daily primary source per instrument before the old FRED/OECD monthly series — OAT 10y = Banque de France TEC10 via the Webstat API (`observations` dataset, `series_key="FM.D.FR.EUR.FR2.BB.FRMOYTEC10.HSTA"`, fields `time_period`/`obs_value`, `obs_value` null on non-quoted days; needs a free key in `WEBSTAT_API_KEY`, sent as `Authorization: Apikey …`, set on Render and as a GitHub secret), Bund 10y = Bundesbank BBSIS CSV (no key, `;` separated, decimal comma). Both verified live from the user's Mac (17/10/2026). Writing rules: a daily source rewrites its whole fetched window (35 days on the daily run, so 24h/7j/30j variations work right away and missed days self-heal) and deletes other-source rows in that window (the FRED monthly averages dated the 1st); the monthly fallback only inserts its latest point when the date is free (`ON CONFLICT DO NOTHING`), never overwriting a daily value, and the run's `error_summary` says "repli". `--backfill` uses Webstat `exports/json` / Bundesbank `startPeriod` for long histories (those two query shapes are not yet verified live). The tolerance for the OAT-Bund spread stays at 45 days because of the fallback. The rewritten `tests/test_bond_yields.py` also fixes the long-standing `test_run_is_idempotent…` failure (its fake CSV now serves every series).
- Threshold editing sends only the changed field(s) (`apiPatch`, `undefined` keys dropped by `JSON.stringify`), matching the API's "only provided fields change" semantics. **`api/main.py` CORS `allow_methods` gained `PATCH`** — without it the browser's preflight is rejected and editing fails in the web app while still working in curl; regression test `tests/test_cors.py` (pure, no Docker). This backend change only takes effect once Render redeploys.
- `Obligataire.test.jsx` uses `getByRole(..., { hidden: true })` for the threshold buttons: jsdom 30 crashes in `getComputedStyle` on some inline styles during the accessibility check — a test-environment bug, not an app one.

### "Trading" tab — CAC 40 table (ad hoc, requested directly by the user)

- **Realised performance (API only)** — `GET /decisions/performance` (`api/routers/decisions.py`), calculations in **`engine/performance.py`** (pure, `tests/test_performance.py`, no DB): only decisions with `status="cloturee"` count, each with its **latest realised** `decision_outcomes` row (`take_profit_hit`/`stop_loss_hit`). `decision_outcomes` also holds `open` rows written by `engine.reevaluate_decisions` for still-open positions (latent returns) and can hold several rows per decision — counting those would double-count or mix latent with realised, the bug this split guards against (API regression test in `tests/test_api.py`, Docker). ### Graphiques sur écran étroit (nov. 2026)
- `hooks/useElementWidth.js` mesure le cadre d'un graphique (ResizeObserver). Il renvoie `null` tant que la largeur est inconnue (jsdom) : chaque graphique garde alors son rendu large. Dans les tests, `src/test/containerWidth.js` simule une largeur.
- Chandeliers (`Univers.jsx`) : la largeur passée est celle du cadre (320 px par défaut), la hauteur reste 150 px.
- Historique obligataire : sous 560 px de cadre (`bondChartLayout.js:layoutFor`), viewBox à la taille réelle (hauteur 240), moins de graduations, légende des dernières valeurs sous le graphique.
- Vérifié avec des données factices sur des captures Chrome headless (360, 390, 768, 1440 px). Pas essayé sur un vrai téléphone : toucher et pincement non vérifiés à la main.
