# Project overview and phase history

Moved verbatim from `CLAUDE.md`.

## What this repository is

"George" is a planned agent for technical analysis of financial markets (pattern detection on OHLCV data, per-basket "George Index" scoring, natural-language rationale for trade decisions). The build follows the 8-phase roadmap in `George_Prompts_Claude_Code.md`. So far: **Phase 0** (DB schema + Docker infra), **Phase 1** (pattern-detection engine + price ingestion), **Phase 2** (backtesting, learned XGBoost confidence score, baskets + George Index), **Phase 3** (FastAPI backend + `web/` wired to it via React Query), **Phase 4** (Mistral-backed LLM layer: decision explainer, `/chat`, pgvector-indexed reports, Jane's second opinion — `agents/`), **Phase 6** (risk management: exit-level calculation, the propose→confirm→monitor→confirm-exit decision lifecycle — `engine/exit_levels.py`, `engine/propose_decisions.py`, `engine/monitor_decisions.py`, this section), a **deliberately scoped-down MVP of Phase 7** (collection orchestrator + validation/quarantine module + 2 manually-triggered sub-agents — `agents/orchestrator/`, `agents/collectors/`, see the Phase 7 section below), and a **simple-access-portal slice of Phase 9** (Supabase-backed login gating mobile and web, no per-user data isolation — `api/auth.py`, see the Auth section below) are implemented. **Phase 5 (mobile app) was deliberately skipped in its original form** — built out of roadmap order, straight after Phase 4, because the user's immediate need was real buy/sell opportunities surfaced through the existing API/web stack, not a mobile client; nothing about Phase 6 depended on Phase 5 having been built first. A **Flutter V1 MVP** of the mobile app was built later (see "Mobile app (Flutter)" section below), deliberately deviating from the roadmap's own Phase 5 stack (React Native/Expo + FCM + Piper/Coqui TTS) at the user's explicit request for Flutter + Firebase — with Firebase itself deferred to a V2 that tackles push notifications, since V1's scope (3 read/action screens against the existing REST API, no auth, no push) doesn't actually need any Firebase product yet. **That mobile app is decommissioned for now (Nov. 2026, user's explicit request)** — see that section for exactly what this does and doesn't mean. The full Phase 7 (LangGraph/Celery/Redis/Airflow/Playwright, 4 activation modes, the scraping-based sub-agents, Jane's continuous methodology watch) remains unimplemented — see that section for exactly what was built instead and why.

Root-level reference material (not code to run):
- `George_Prompts_Claude_Code.md` / `George_Prompts_Claude_Pro.md` — the full 8-phase roadmap (Phase 0 DB/Docker foundations → Phase 1 pattern-detection engine → Phase 2 ML scoring & George Index → Phase 3 FastAPI + React web app → Phase 4 LLM layer → Phase 5 mobile app (skipped, see above) → Phase 6 risk management/exit scenarios → Phase 7 geopolitical/press monitoring agents). Read the relevant phase section before implementing the next piece — it specifies exact table schemas, endpoints, and pattern lists.
- `Jane_Synthese_Connaissances.md` — Jane's full knowledge corpus (portfolio theory, performance measures, market-efficiency critique, Fujimoto method) referenced by `agents/prompts/jane_second_opinion_system.txt`; `Jane_financeMarche.docx` is the unread `.docx` source behind it (Read tool can't open `.docx`).
- `George_AnalyseTechnique_Kabbaj_Synthese.md` — synthesis of Thami Kabbaj's *Maîtriser l'analyse technique* (2011, Eyrolles), source PDF at `ingestion/skills/AnalyseTechnique_Kabbaj.pdf`. Cross-checks the book's worked examples against George's 13 existing pattern detectors (measured-move formulas for Double Top/Bottom and Head & Shoulders confirmed consistent, no contradictions found) and catalogs what's *not* yet implemented as candidate future work: 9 candlestick patterns (doji, hammer, engulfing, evening/morning star...), Elliott Wave + Fibonacci retracements, an RSI-based "stabilisation/accélération" divergence variant, RSI-derived price objectives, pair trading, and the Livermore pyramiding position-sizing method. Not wired into any code yet — reference only, same tier as `Jane_Synthese_Connaissances.md`.
- `George_Strategies_Images_Synthese.md` — synthesis of two image batches. **§0-4**: 16 social-media reference images in `stratégies_images/` (Fair Value Gap, Breakaway Gap, Order Blocks and other ICT/Smart Money Concepts, plus chart/candlestick patterns) — unlike the Kabbaj synthesis, several source labels were unreliable (social-media/AI-generated captions, garbled OCR-looking terms like "Invested Hunler", "Dock Wave"), flagged explicitly in §3; **this batch's 35 candidate concepts have since actually been implemented** (see the "35 new pattern detectors" section below) — the doc's §4 tracks what was/wasn't built and why, don't read §0-3 alone and assume nothing is wired in. **§5**: a second batch, 22 personal-gallery diagrams (2026-08-23) analyzed directly by a multimodal agent and written straight into `jane_knowledge` (`data/jane_diagrammes/import_2026-08-23.json`) rather than staying documentation-only — its candidates (Pivot Points, Volume Profile, ADX, EMA 9/21) are indicators, not chart-pattern geometry, and remain unimplemented.
- `george_web_interface.html` and `GeorgeDashboard.jsx` — the two standalone prototypes (vanilla JS/SVG terminal UI, and a React/Recharts portfolio view) that `web/` was built by merging. Kept for reference; not part of any build.
- `edgar_client.py` — standalone SEC EDGAR (company facts / 10-K) client, not yet integrated into any pipeline. Has hard SEC rate-limit/User-Agent requirements documented in its own docstring — follow them if extending it.
- `whitelist_journaux.md` / `whitelist_journaux.json` — per-country reference list of national newspapers for the future "pilier 7" geopolitical-events agent (Phase 7). Not wired into any code yet.
- `George_Pitch_*.pdf`, `George_Portefeuille_*.docx`, `George_Stack_Technique.*` — pitch deck and stack-decision documents.
- `TODO.md` — pending follow-up work not yet in scope for any current change (currently: correlating `jane_second_opinions` with `decision_outcomes` once enough closed decisions accumulate). Check before assuming a listed item still needs doing — update or remove entries once addressed.
