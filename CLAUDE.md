# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

"George" is a planned agent for technical analysis of financial markets (pattern detection on OHLCV data, per-basket "George Index" scoring, natural-language rationale for trade decisions). The build follows the 8-phase roadmap in `George_Prompts_Claude_Code.md`. So far: **Phase 0** (DB schema + Docker infra), **Phase 1** (pattern-detection engine + price ingestion), **Phase 2** (backtesting, learned XGBoost confidence score, baskets + George Index), and **Phase 3** (FastAPI backend + `web/` wired to it via React Query, this section) are implemented. `agents/` and `mobile/` are still empty placeholders (each has a one-line README) for phases not started yet.

Root-level reference material (not code to run):
- `George_Prompts_Claude_Code.md` / `George_Prompts_Claude_Pro.md` — the full 8-phase roadmap (Phase 0 DB/Docker foundations → Phase 1 pattern-detection engine → Phase 2 ML scoring & George Index → Phase 3 FastAPI + React web app → ... → Phase 7 geopolitical/press monitoring agents). Read the relevant phase section before implementing the next piece — it specifies exact table schemas, endpoints, and pattern lists.
- `george_web_interface.html` and `GeorgeDashboard.jsx` — the two standalone prototypes (vanilla JS/SVG terminal UI, and a React/Recharts portfolio view) that `web/` was built by merging. Kept for reference; not part of any build.
- `edgar_client.py` — standalone SEC EDGAR (company facts / 10-K) client, not yet integrated into any pipeline. Has hard SEC rate-limit/User-Agent requirements documented in its own docstring — follow them if extending it.
- `whitelist_journaux.md` / `whitelist_journaux.json` — per-country reference list of national newspapers for the future "pilier 7" geopolitical-events agent (Phase 7). Not wired into any code yet.
- `George_Pitch_*.pdf`, `George_Portefeuille_*.docx`, `George_Stack_Technique.*` — pitch deck and stack-decision documents.

## Python backend (`ingestion/`, `infra/`, `tests/`) — Phase 0

### Commands
Run from the repo root:
```
cd infra && docker compose up -d      # Postgres+TimescaleDB, Redis, MinIO, Adminer
python -m venv .venv && .venv\Scripts\activate
pip install -e ".[dev]"
alembic upgrade head                  # apply migrations (needs the db container running)
python -m ingestion.seed              # load the 40 CAC 40 securities (idempotent)
pytest                                # needs a local Docker daemon (testcontainers spins up its own Postgres)
```
`alembic upgrade head --sql` / `alembic downgrade base --sql` print the migration SQL without needing a DB connection — useful to sanity-check a new migration when Docker isn't available.

### Architecture
- **`ingestion/models.py`** is the single SQLAlchemy declarative source of truth for the schema (`Security`, `PriceOHLCV`, `PatternDetected`, `Decision`, `DecisionOutcome`) — the Alembic migration in `ingestion/migrations/versions/0001_initial_schema.py` was written by hand to match it (not autogenerated), including the `create_hypertable('prices_ohlcv', 'ts')` call that makes `prices_ohlcv` a TimescaleDB hypertable. If you change `models.py`, write the matching migration by hand rather than relying on `alembic revision --autogenerate` to get the hypertable call right.
- **`ingestion/db.py`** resolves the connection string from the `DATABASE_URL` env var at call time (`get_database_url()`), falling back to the default local Docker Compose credentials. `alembic.ini` (repo root) does not hardcode a real URL — `ingestion/migrations/env.py` overrides it via `get_database_url()` on every invocation, online or offline. `get_engine()` sets `connect_args={"connect_timeout": 5}` — without it, psycopg trying both the IPv6 and IPv4 loopback addresses against a port nothing is listening on can hang far longer than 5s; this bit the notebook's DB-or-fallback logic (below) before the timeout was added, so keep it if you touch this function.
- **`ingestion/cac40.py`** holds the seed list of 40 `(symbol, name, country, currency, sector)` tuples; `ingestion/seed.py` upserts them into `securities` on conflict (safe to re-run).
- **Tests** (`tests/test_migrations.py`, `tests/test_seed.py`) use `testcontainers.community.postgres.PostgresContainer` (image `timescale/timescaledb:latest-pg16`) to get a disposable database per test session — they require a working local Docker daemon and are independent of whatever is running via `infra/docker-compose.yml`. Each test upgrades to `head` and downgrades back to `base` itself, so tests don't depend on execution order.

## Quant engine (`engine/`) + price ingestion (`ingestion/ohlcv.py`) — Phase 1

### Commands
```
python -m ingestion.ohlcv             # download 2y daily OHLCV via yfinance for every security, upsert into prices_ohlcv (needs network + db)
python -m engine.run_detection        # run all 13 pattern detectors against prices_ohlcv, insert confirmed matches into patterns_detected (needs db)
pytest tests/test_patterns.py         # unit tests on synthetic price series — no DB, no Docker, no network needed
pip install -e ".[dev,notebook]"      # adds mplfinance/jupyter for engine/notebooks/pattern_validation.ipynb
```

### Architecture
- **`engine/patterns/common.py`** holds the shared geometry toolkit and the module-level tolerances every detector reads (`EXTREMA_ORDER`, `LEVEL_TOLERANCE`, `MIN_PATTERN_BARS`, `BREAKOUT_BUFFER`) plus `PatternMatch` (the dataclass every detector returns). Pattern-specific thresholds (e.g. `MIN_PEAK_PROMINENCE`, `MIN_CUP_DEPTH` in `reversal.py`; `MIN_TREND_SLOPE`, `MIN_CONVERGENCE` in `continuation.py`) are documented in each file's module docstring, not centralized — read the docstring before tuning a specific pattern.
- Detectors are split by shape: **`reversal.py`** (Double Top/Bottom, Head & Shoulders + inverse, Cup & Handle — scan the *whole* price history for the most recent qualifying formation, since these can form anywhere in the past and only need a breakout on the latest bar to confirm), **`continuation.py`** (Bull/Bear Flag, Ascending/Descending Triangle, Falling/Rising Wedge — only look at a recent tail window, since these are short-lived), **`breakout.py`** (Breakout/Breakdown — recent tail window, requires a pullback bar immediately before the break so a plain continuous grind doesn't trivially count as a "breakout"). All 13 are registered in `engine/patterns/__init__.py`'s `DETECTORS` dict and re-exported from there.
- **Every detector returns at most one match** (the most recent formation), not every historical occurrence — each one filters/iterates backward and returns on the first (i.e. most recent) qualifying formation. `engine/detect.py:detect_all` just concatenates one call per registered detector.
- **Trendlines are fit through the actual extrema points** (`common.fit_trendline`, `np.polyfit` on `(extrema_index, price)` pairs), not through the whole window — this matters for wedges/triangles/flags. A recurring trap already hit once while building this: computing "does the range narrow / is the channel tight" using the *raw high/low of a window that still includes the breakout bar* silently defeats the check, because the breakout bar's whole purpose is to exceed the channel. Wedge convergence is measured strictly between the first and last **extrema** (`continuation.py:_wedge`), and a flag's channel (`continuation.py:_flag`) is fit only over the consolidation bars, explicitly excluding the final (candidate breakout) bar — apply the same exclusion if you add another breakout-confirmed continuation pattern.
- **`engine/confidence.py`** turns a detector's own `geometry_quality` (0-1, pattern-specific) plus shared `volume_confirmation` and `trend_alignment` (both also 0-1) into the final 0-100 score via fixed weights (0.5/0.25/0.25). `trend_alignment` needs 200 bars of history to judge SMA50/SMA200 alignment and returns a neutral 0.5 below that — expect near-identical confidence scores across patterns when testing on short synthetic series.
- **`ingestion/ohlcv.py`** downloads per-symbol via `yf.Ticker(symbol).history(...)`, retries up to `MAX_RETRIES` with linear backoff, and treats an empty/missing result as a soft failure (logged, symbol skipped, rest of the universe continues) rather than raising.
- **`tests/test_patterns.py`** builds each pattern from hand-placed `ramp()`/`path()` segments (strictly monotonic pieces glued end-to-end so `scipy.signal.argrelextrema` finds extrema exactly where intended) rather than random walks — when adding a test for a new detector, follow that construction style and hand-verify the key indices/levels against the detector's own gates instead of guessing coordinates.
- **`engine/notebooks/pattern_validation.ipynb`** tries the real DB first (via `engine.run_detection.load_prices`) and falls back to a synthetic Double Bottom (same construction as the test above) if it's unreachable or empty — verified executable end-to-end with `jupyter nbconvert --to notebook --execute`. Its `plot_match` helper only sets `hlines=`/`addplot=` on the `mpf.plot(...)` call when those lists are non-empty — mplfinance's kwarg validator rejects `hlines=None` outright rather than treating it as "no lines", which crashed the first version of this cell.

## Learned scoring, baskets & George Index (`engine/`) — Phase 2

### Commands
```
python -m engine.build_training_set   # DB -> engine/data/training_set.parquet (patterns_detected + prices_ohlcv backtested at 5/10/20 sessions)
# then run engine/notebooks/train_confidence_model.ipynb (offline) to train + save engine/models/confidence_xgb_<date>.joblib (+ .meta.json)
python -m engine.compute_george_index # prints each basket's George Index (needs db + baskets/basket_securities populated)
python -m engine.reevaluate_decisions # updates decision_outcomes for existing decisions (needs db)
pytest tests/test_features.py tests/test_backtest.py tests/test_george_index.py tests/test_scoring.py   # no DB, no Docker
```
`engine/models/` and `engine/data/` are gitignored (regenerable binaries/derived data) — running the training notebook with no `engine/data/training_set.parquet` present falls back to a synthetic dataset with a small fabricated signal, so the whole pipeline (train → evaluate → save dated model + metadata → load in `engine.scoring` → override a detector's confidence) is exercisable and was verified end-to-end without Docker.

### Architecture
- **`engine/features.py`** is the single source of the feature contract shared between training and inference: `FEATURE_COLUMNS` (= `CATEGORICAL_FEATURE_COLUMNS` + `NUMERIC_FEATURE_COLUMNS`). Its functions (`relative_volume`, `atr_pct`, `position_vs_moving_averages`) return `None` on insufficient history rather than a placeholder value — that `None` is exactly the signal `engine/scoring.py` uses to trigger the Phase 1 heuristic fallback instead of the learned model.
- **`engine/backtest.py`** is pure (no DB) — `build_sample` turns one detected pattern into a training row (features + `return_{5,10,20}` + `success_{5,10,20}` labels), gated on the pattern being far enough in the past that the longest horizon is observable. `compute_market_trend` is a deliberate proxy for "reference index trend" (cross-sectional average return of whatever price series you hand it) because the schema has no dedicated market-index feed — same limitation called out in `engine/george_index.md`. `engine/build_training_set.py` is the DB-touching script that resolves each `patterns_detected.detected_at` to an integer bar position (`nearest` on the DatetimeIndex) and calls into `backtest.py`. **It skips writing `training_set.parquet` entirely when zero samples are backtestable** (real case: right after a fresh `engine.run_detection` run, every pattern's `detected_at` is today, so none has `TRAINING_HORIZON` sessions of hindsight yet) — writing an empty, columnless DataFrame there would satisfy the training notebook's `os.path.exists(...)` fallback check while still crashing it on `dataset[FEATURE_COLUMNS]` a few cells later; the notebook now also guards with `not dataset.empty` before trusting the file, and falls back to the synthetic dataset otherwise.
- **`engine/scoring.py`** loads the lexicographically-last `engine/models/confidence_xgb_*.joblib` (filenames are ISO dates, so sorted-last == most recent) plus its `.meta.json` (`feature_columns`), caches both for the process, and never raises — any missing model, insufficient per-symbol history, or prediction-time exception falls back to `match.confidence` (the Phase 1 heuristic, already computed by the detector). `predict_confidence`'s `price_frames` param is optional: passing it enables the `market_trend` feature, omitting it just leaves that one feature as `NaN` (imputed by the trained pipeline) rather than blocking inference — only the *other* features (volume/ATR/moving averages) are treated as hard requirements.
- **The saved model artifact is a full scikit-learn `Pipeline`** (`ColumnTransformer(SimpleImputer + OneHotEncoder) → XGBClassifier`), not a bare `XGBClassifier` — this is why `engine/scoring.py` can call `.predict_proba()` directly on a raw one-row DataFrame with string `pattern_type`/`sector` columns without re-implementing the encoding at inference time. If you retrain with a different feature set, update `engine/features.py:FEATURE_COLUMNS` (both training and inference read from there) rather than hardcoding column lists in the notebook or in `scoring.py`.
- **`engine/george_index.py`** implements the formula documented in `engine/george_index.md` — read that file first; the two must stay in sync. Key asymmetry: the confidence part of the score only counts securities with a pattern detected within `ACTIVE_WINDOW_SESSIONS` (5 sessions), but the momentum/volume multipliers are computed over *every* security in the basket with enough price history, active or not — a basket's price-action context isn't limited to its currently-alerted names. Returns `None` (not `0`) when no security in the basket has an active pattern — a silent basket isn't a bad one.
- **`engine/reevaluate_decisions.py`** and **`engine/compute_george_index.py`** are thin DB scripts — `baskets`/`decisions` stay empty unless you run `ingestion/seed_demo.py` (Phase 3) or wait for Phase 6 to generate real decisions; verified here only by import and by unit-testing their pure helper functions (`evaluate_decision`, `george_index.compute_george_index`) directly, not against a live DB.
- **`ingestion/models.py`** gained `Basket`, `BasketSecurity`, `PatternCandidate` in migration `0002` (chained after `0001` via `down_revision`). `pattern_candidates` mirrors `patterns_detected`'s columns exactly — it's a landing/backtesting table for whatever the future Phase 7 methodology-watch agent proposes, nothing promotes rows into it yet.

## API (`api/`) — Phase 3

### Commands
```
uvicorn api.main:app --reload     # dev server on :8000, needs db running (needs Docker)
python -m ingestion.seed_demo     # optional: seeds baskets (one per sector) + a few illustrative decisions/agent_events, so the API isn't just empty lists
pytest tests/test_api.py          # most need Docker (testcontainers); one doesn't (see below)
```
`GET /docs` (Swagger UI) and `/openapi.json` are generated automatically by FastAPI — `app.openapi()` builds successfully with zero DB access (verified by importing `api.main` with no DB running), since routes only touch the DB when actually called.

### Architecture
- **`api/deps.py`** builds the SQLAlchemy `engine`/`SessionLocal` once at import time (not per-request) and exposes both as module attributes — `api/routers/baskets.py` reuses the same engine directly (not the per-request ORM `Session`) to call into `engine.george_index`/`engine.run_detection`, which expect a raw Engine. Tests override `api.deps.engine`/`api.deps.SessionLocal` via `monkeypatch` (see `tests/test_api.py`) since they're bound at import time, before a test DB URL is known. **`baskets.py` does `from api import deps` and reads `deps.engine` at call time — not `from api.deps import engine`.** The latter copies the reference at import time into `baskets.py`'s own namespace; a later `monkeypatch.setattr(deps, "engine", ...)` then silently misses it, and the route keeps querying whatever DB was live at process startup. Caught by running the real Phase 0-3 stack end-to-end (Docker actually available): `test_george_index_for_basket_with_active_pattern` passed against the isolated test container's `SessionLocal`-backed queries but returned `george_index: null` because `load_patterns`/`load_prices` were silently hitting the stale pre-monkeypatch engine instead.
- **`api/schemas.py:Page[T]`** is the one pagination envelope used by every list endpoint (`{"items": [...], "total", "limit", "offset"}`). Routers return a *bare* `Page(items=rows, ...)` (not the parameterized `Page[SecurityOut](...)`) with `rows` being raw ORM objects — this works because FastAPI re-validates the returned object against the route's declared `response_model=Page[SecurityOut]` regardless of how it was constructed, and that re-validation is what triggers `SecurityOut`'s `from_attributes` conversion. Verified with an isolated repro against this exact FastAPI/pydantic version pair before relying on it.
- **`GET /securities/{symbol}/prices`** exists beyond the roadmap prompt's minimum endpoint list — the candlestick chart (task 6 of the Phase 3 prompt) needs real OHLCV, and no endpoint for it was specified. It returns the `limit` most recent bars in chronological order; the frontend must reconstruct each bar's *absolute* index (`total - len(items)` from the same `Page` envelope) to translate a pattern's `context` indices (absolute positions in the full series the detector saw) into positions within this truncated window — see `CandlestickChart.jsx` below.
- **`GET /securities/{symbol}/patterns` orders by `detected_at.desc(), confidence.desc()`, not `detected_at.desc()` alone.** `engine/run_detection.py` typically confirms several pattern types for the same symbol with the exact same `detected_at` (all resolve off the same latest bar) — against a real populated DB, `limit=1` with only `detected_at` ordering returned an effectively arbitrary tied row (observed: consistently the *lowest*-confidence one, e.g. a 19% Double Bottom shown in the watchlist for a symbol that also had a 48% Inverse Head & Shoulders). The confidence tiebreaker makes "the pattern for this symbol" deterministic and picks the most convincing one instead. `tests/test_api.py::test_list_security_patterns_prefers_higher_confidence_on_tie` is the regression test.
- **`api/main.py:database_exception_handler`** is registered for `SQLAlchemyError`, deliberately *not* the bare `Exception` class — Starlette special-cases handlers registered for `Exception` (or status 500) and routes them to `ServerErrorMiddleware`, which sits *above* `CORSMiddleware` in the stack, so its response never gets CORS headers added (the browser then reports a misleading CORS error instead of surfacing the real 503, since with no DB running every list endpoint fails this way). Registering the handler on a specific subclass instead keeps it inside `ExceptionMiddleware`, *below* `CORSMiddleware`, so headers get added correctly. `tests/test_api.py::test_db_unreachable_returns_503_with_cors_headers` is the regression test — it needs no Docker (it points `api.deps.engine` at a deliberately-closed port) and will fail if this handler regresses to catching bare `Exception` again.
- **`ingestion/db.py`'s default `DATABASE_URL` host is `127.0.0.1`, not `localhost`** — `localhost` also resolves to `::1`, and psycopg tries both addresses in sequence on failure, doubling the time before a connection error surfaces (relevant because the API, the notebooks, and every script share this default). Combined with React Query's `retry: 0` (`web/src/main.jsx` — a second client-side attempt would double the already-multi-second server-side failure again), a cold "DB is down" page load now settles in roughly one `CONNECT_TIMEOUT_SECONDS` instead of stacking multiple retries at multiple layers.
- **`ingestion/seed_demo.py`** groups the existing `securities` by their `sector` column into one basket per sector — it doesn't invent a separate taxonomy. Decisions are only inserted for symbols that already have `prices_ohlcv` history (real `entry_price`, computed `take_profit`/`stop_loss` off it); a symbol with no price history is silently skipped rather than seeded with a fabricated entry price. Both the basket-seeding and decision-seeding steps check what already exists before inserting, so the script is safe to re-run.
- **`ingestion/models.py`** gained `AgentEvent` in migration `0003` (chained after `0002`). It backs `GET /agents/activity`; nothing populates it yet outside `seed_demo.py`'s illustrative rows, pending the Phase 7 sub-agents.

## `web/` — the front-end app

### Commands
Run from `web/`:
```
npm install       # install deps
npm run dev       # Vite dev server on :5173 (matches api/main.py's CORS allowlist — using another port needs a matching change there)
npm run build     # production build (outputs to dist/)
npm run preview   # serve the production build locally
npm run lint      # oxlint (see .oxlintrc.json)
npm run test      # vitest run — component tests, hooks mocked, no API/Docker needed
```
Copy `.env.example` to `.env` to override `VITE_API_BASE_URL` (default `http://localhost:8000`, read in `src/api/client.js`).

### Stack
Vite + React 19 + Tailwind CSS v4 (via `@tailwindcss/postcss`) + Recharts (donut chart in Paniers) + [`@tanstack/react-query`](https://tanstack.com/query) (all API calls/caching — task 9 of the Phase 3 prompt) + Vitest/React Testing Library/jsdom (dev-only, task 10). No router — view switching is plain `useState` in `App.jsx`. No `lucide-react` any more (dropped with the Paniers rewrite below — check before re-adding an icon library that nothing else needs it).

### Architecture
- **`src/api/client.js`** is a thin `fetch` wrapper (`apiFetch(path, params)`) — throws on any non-OK response so React Query's `isError` fires correctly. **`src/api/queries.js`** has one React Query hook per API endpoint (`useSecurities`, `useSecurityPatterns`, `useSecurityPrices`, `useBaskets`, `useGeorgeIndex`, `useDecisions`, `useAgentActivity`). There's no batch endpoint for "pattern + price history for N securities at once", so `WatchlistRow` and `GeorgeIndexTile` each call their own per-item hook — real N+1 request behavior, acceptable at CAC-40 scale, called out in `queries.js`'s docstring as something to revisit if the tracked universe grows a lot.
- **`src/components/CandlestickChart.jsx`** no longer generates synthetic candles from a seeded PRNG (that whole approach — and `src/lib/ohlc.js` — is gone). It now takes real `candles` (from `/securities/{symbol}/prices`) plus the real `context` dict from `patterns_detected`/`PatternOut.context`, and derives the overlay generically from that context's shape rather than regex-matching the pattern name: a `{index, price}` value becomes a marker (translated by the `indexOffset` prop — see the API section above for why that offset is needed), a `{points, price}` value (a neckline) becomes markers *and* a horizontal line, and a bare number under the key `resistance`/`support` becomes a line with no marker. No context at all (no active pattern) means no overlay at all — it no longer fabricates one from local extrema, unlike the Phase-3-prototype version. `takeProfit`/`stopLoss` are now absolute prices (from `Decision`), not the old `tpPct`/`slPct` percentages off a synthetic last close.
- **`src/views/Univers.jsx`** fetches `useSecurities`, `useDecisions` (built into a `symbol -> most-recent-decision` map client-side — there's no per-symbol decision filter on the endpoint, and the full list is small enough to fetch once), `useBaskets`, `useAgentActivity` at the top level; `WatchlistRow`/`GeorgeIndexTile` (in `src/components/`) own their own per-item queries. The George Index tile grid always renders exactly 2 slots (real tile, or an empty filler `<div>`) plus the macro tile — the grid's `gridTemplateColumns` is the fixed `"150px 150px 1fr"`, so a *variable* number of basket tiles (0, 1, vs. 2) shifts the macro tile into the wrong column; the empty-baskets message instead spans both slots via `col-span-2`. Distinguishes "API unreachable" (`isError`) from "DB reachable but empty" (`data.items.length === 0`) with two different messages — collapsing them into one generic empty state would hide a real connectivity problem.
- **`src/views/Paniers.jsx`** was rewritten from a fictive-portfolio simulator (invented capital, position weights, cash reserve — none of that has a backing table in the schema) into a real-data basket/decision browser: George Index per basket (bars, real), universe breakdown by `sector` (donut, real, computed client-side from the single `/securities` fetch rather than a per-basket count query), and a real `/decisions` table. Same "unreachable vs. empty" distinction as `Univers.jsx` (`apiUnreachable = basketsError || securitiesError || decisionsError`).
- **`src/data.js`** now only holds `macro` (rates/indices/FX tile — no backing table exists in the schema for this, so it stays a labeled placeholder) and the `decisionColor`/`scoreColor` helpers shared by both views. Everything else that used to live here (`positions`, `georgeIndex`, `agentEvents`, `CAPITAL`) is gone now that real data is wired up.
- **Theming** is CSS custom properties defined once in `src/index.css` (`--bg`, `--panel`, `--positive`, `--negative`, etc.), consumed via inline `style={{ color: "var(--x)" }}` or Tailwind arbitrary values rather than a Tailwind theme extension. Keep new components consistent with this pattern instead of introducing hex literals or extending `tailwind.config`.
- **Tests** (`*.test.jsx` next to the files they cover) mock `../api/queries` wholesale with `vi.mock` rather than standing up a `QueryClientProvider` + mocking `fetch` — simpler, and sufficient since the hooks themselves are trivial wrappers with no logic of their own to test. `vi.mock` is keyed by resolved module path, so mocking `"../api/queries"` from e.g. `Univers.test.jsx` also mocks it for `WatchlistRow`/`GeorgeIndexTile` that `Univers` renders, even though those files import it via the same relative specifier resolving to the same file — no separate per-component mock wiring needed.

Any data still explicitly fictive/illustrative (macro tile, `seed_demo.py` output) says so in the UI or in code comments — don't remove those disclaimers or present them as real.
